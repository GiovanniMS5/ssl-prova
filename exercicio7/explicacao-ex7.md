Na VM 1, o erro SSL_ERROR_RX_RECORD_TOO_LONG acontece porque o navegador enviou um pedido criptografado (HTTPS) esperando uma resposta segura, mas o servidor Python respondeu em texto simples (HTTP). Quando o navegador recebe texto puro onde deveria haver uma camada de criptografia, ele fica confuso com o tamanho dos pacotes de dados e interrompe a conexão por segurança, acreditando que os dados estão corrompidos ou que algo está errado.

Na VM 2, as linhas estranhas com códigos como \x16\x03\x01 são a prova real desse "desencontro". Esses caracteres são, na verdade, o navegador tentando iniciar o aperto de mão do SSL (SSL Handshake); como o comando python3 -m http.server só entende requisições HTTP comuns (como um simples GET /index.html), ele não sabe o que fazer com esses códigos binários de segurança e acaba registrando um code 400, message Bad request version, basicamente dizendo que não entendeu a versão da requisição enviada.
